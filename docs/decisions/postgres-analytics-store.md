PostgreSQL is the analytics store because one transaction can preserve raw input, assign dispositions, update accepted business rows, refresh affected reporting dates and enforce the quality gate before commit. Explicit constraints and separate owner, ETL and read-only roles make invalid writes and unintended access testable; the application never needs the bootstrap administrator. PostgreSQL 18's `RETURNING OLD/NEW` supports identifying dates affected by order updates. SQL aggregates and warm-cache `EXPLAIN (ANALYZE, BUFFERS)` measurements remain reproducible on the local dataset; the [query results](../benchmarks.md#1-query-tuning-with-indexes-metrics-and-analytics-layer) do not imply production-scale performance.
