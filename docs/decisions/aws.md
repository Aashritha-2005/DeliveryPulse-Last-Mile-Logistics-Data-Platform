The optional AWS proof was first skipped on 2026-10-15, when the S3 API path was proven locally against SeaweedFS. It was reopened on 2026-10-25 and **run by the owner on 2026-10-28** in ap-southeast-2 (Sydney) on an AWS Free plan account ([runbook](../../infra/aws/README.md), [measured results](../benchmarks.md#5-aws-proof-s3-export-and-one-athena-query-2026-10-28)). Terraform created 12 resources: one private bucket, a Glue database and table, an Athena workgroup with a 100 MiB per-query limit, and a least-privilege pipeline role. The pipeline role passed the preflight and all five permission-denial checks. The existing export code wrote the 5,000-order demo lake (118 objects, 168,257 rows, 7,682,232 bytes) after its dataset-identity guard passed. One Athena query returned the late-delivery rate by city, identical to PostgreSQL, scanning 10,143 bytes (estimated USD 0.000048). Terraform then destroyed all 12 resources, and the read-only teardown check found nothing left. Credentials were short-lived only (`aws login` and the role's temporary credentials) and `S3_ALLOW_AWS` was given explicitly on each command. The billed amount is to be confirmed from the console 24–48 hours after the run.

**Encryption exception (accepted 2026-10-25).** The proof bucket uses SSE-S3 (AES-256 with keys managed by S3) rather than a customer-managed KMS key, so Trivy's check AWS-0132 fails on `infra/aws/main.tf`. A customer-managed KMS key is billed monthly and per request, and the proof runs on the Free plan where nothing may be paid. The data is synthetic, encrypted at rest, private (Block Public Access) and TLS-only, expires after 7 days and is destroyed after the proof, so the paid key adds no meaningful protection here. The exception is committed in `.trivyignore.yaml`, scoped to that one check in that one file; a unit test fails if any other ID, path or section is added.
