Lake keys put the table before the date so each prefix has one schema. Raw data uses the deterministic batch-cutoff ingestion date in Asia/Kolkata, cleaned orders and events use their documented reporting date, aggregates use `metric_date`, and drivers remain unpartitioned. The batch cutoff comes from source metadata rather than wall-clock export time, preserving replay keys. These dates have different meanings and are never described as interchangeable; the [layout](../operations.md#object-storage-lake) documents each one. Partition pruning is a potential benefit, not a measured win here: the recorded week-of-data read did not improve materially because single-file row-group statistics already skipped data and partitions created many small files.
